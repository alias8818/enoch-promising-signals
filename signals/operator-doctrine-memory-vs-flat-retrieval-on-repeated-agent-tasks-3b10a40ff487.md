## What looked useful

Mutable operator doctrine should not be treated as ordinary flat top-k retrieval over all memories. Recency-aware targeted retrieval or keyed doctrine state is enough to fix the generated failure mode, so the evidence supports the mechanism but not a paper-ready architecture claim.

## Boundaries and scale limits

Synthetic local corpus only; no real operator traces, live LLM execution, embedding/hybrid retrieval baseline, human scoring, or production-scale latency and maintenance analysis.

## Claim scope

On a deterministic synthetic repeated-agent replay with mutable project doctrine, undifferentiated flat lexical retrieval performed poorly while a keyed doctrine-memory table recovered the current rule exactly; a simple reverse transcript search also solved this proxy.

## Why it stopped

No-paper useful signal from a proxy benchmark: flat retrieval was early-falsified on generated mutable doctrine tasks, but synthetic data and the transcript-search control prevent a full validation or unique layered-memory claim.

## Recommended next action

Stop this worker run; run a bounded direct-evidence follow-up using hand-authored or real repeated-agent traces with embedding flat retrieval, targeted transcript search, keyed doctrine memory, and live LLM answer scoring.
