## What looked useful

Freshness must be treated as a separate signed/verified property for summary-claim memory. Claim signatures alone improve integrity but leave stale signed claims unsafe after later trace revisions.

## Boundaries and scale limits

Synthetic realistic traces, deterministic extractor, local HMAC signatures, no live LLM extraction, no private production traces, no signing-key compromise model, and no recovery flow beyond abstention.

## Claim scope

In a deterministic 1000-trace repeated-agent proxy benchmark, HMAC-signed summary claims detected direct value tampering, but signed claims alone did not prevent stale valid claims; adding a signed latest-sequence manifest converted stale/tampered memory into rejections with zero unsafe wrong answers in this harness.

## Why it stopped

Proxy evidence supports the mechanism but is not publication-grade because claims were deterministically extracted from synthetic traces rather than generated by an LLM on real trace corpora.

## Recommended next action

Stop this worker run as no-paper useful signal; next bounded test should use an actual LLM extractor on held-out realistic traces and measure extraction errors plus stale-memory rejection/recovery.
