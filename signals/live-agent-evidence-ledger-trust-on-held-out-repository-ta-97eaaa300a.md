## What looked useful

Execution evidence bound to source, diff, command, exit code, and output hashes materially improved trust acceptance decisions over diff-only and ledger-without-tests controls on held-out repository tasks.

## Boundaries and scale limits

This run used synthetic source mutations and deterministic candidate repairs/decoys, not natural issue tasks or live LLM-generated patches. It validates the trust mechanism against real repository tests but does not establish live-agent behavioral gains or human trust calibration.

## Claim scope

On 23 deterministic mutation-repair tasks across three held-out public Python repositories, a command-backed evidence ledger accepted only candidates with passing repository tests and rejected all failing candidates, while a diff-only trust baseline had a 69.0% false-accept rate.

## Why it stopped

Mechanism supported, but this remains no-paper evidence because candidate patches were deterministic synthetic controls rather than live-agent solutions to natural repository tasks.

## Recommended next action

Run one final bounded depth-4 live-agent validation on natural held-out issue/PR tasks, comparing ledger-required acceptance against transcript-only acceptance for LLM-generated patches.
