## What looked useful

The final direct small test found a ceiling effect: stateless and memory conditions both completed 2/2 tasks with clean target edits, audit lines, decoys, and protected files. Memory mean elapsed time was lower, but sample size is too small for a timing claim.

## Boundaries and scale limits

Only two tasks per condition, one model/client configuration, easy text-file tasks, no long sequence, no hard ambiguity, no private operator workload, and no statistical power for latency claims.

## Claim scope

In a controlled 2x2 live nested-Codex filesystem benchmark with simple manifest-resolved record edits, adding an OPERATOR_MEMORY.md doctrine file did not improve success rate over AGENTS.md-only doctrine because both conditions achieved 100% success.

## Why it stopped

Tier 1 direct test completed; result is a no-paper useful signal because the benchmark ceiling prevents evidence of a memory success benefit.

## Recommended next action

Run a harder bounded deepen test with at least 8 adversarial repeated filesystem tasks per condition and a predeclared memory-over-stateless success threshold.
